# 启动与扩张：原创运营工作法

仅阅读对应分支。以下问题、表格、实验和验收逻辑是本 skill 的设计，理论入口见 [sources.md](sources.md)。数值应根据项目定义。

## A. 验证首个网络

### 从需求失败开始

已有使用时，收集最近几次真实记录：来做什么、需要谁配合、在哪一步失败。分别记录「没有想要的东西」「有但找不到」「找到却不可信」「可信却无法完成」。

尚未启动时，优先使用目标用户现有替代做法、真实访谈或观察；这些材料也没有时，交付候选网络与最小需求验证方案，标记用户、痛点和关键角色假设。不要索要不可能存在的产品使用记录，也不要把计划中的访谈写成已完成证据。先验证需求和可兑现的首次结果，再判断是否形成稳定网络。

| 设计字段 | 必须回答的问题 |
|---|---|
| 对象 | 哪类人有相似且反复发生的需求？ |
| 边界 | 在什么地点、时段、组织或主题内需要彼此？ |
| 关键角色 | 谁退出会使别人最先得不到结果？证据是什么？ |
| 有效参与 | 需要什么资格、库存、在线时间或响应能力？ |
| 价值事件 | 什么可观察事件意味着真正得到帮助？ |
| 兑现路径 | 进入 → 找到对象 → 完成互动 → 得到结果，各步谁负责？ |
| 再次使用 | 用户下次自然需要这一结果的时间？ |

边界过宽时，比较需求相似性、参与者可达性与结果兑现能力，选择团队能服务好的单元。保留放弃其他候选的理由，避免事后把成功子群包装成整体成功。

### 给关键角色持续参与的理由

有访谈材料时，区分收益不足、风险太高、工作量大、质量不可控或缺少合适对象；无材料时，将最影响方案的障碍假设转成访谈问题或小试点，不直接宣布根因。让方案优先验证并解决一个实际障碍。

| 可选措施 | 应观察的结果 | 容易漏掉的问题 |
|---|---|---|
| 辅助整理资料、简化入驻 | 首个有效贡献及后续自主贡献 | 注册提升却没有持续服务 |
| 限定响应窗口和可服务范围 | 履约率、实际耗时、失败原因 | 过度承诺造成更差体验 |
| 预约固定参与时段 | 等待、互动成功、活动后复用 | 只有活动期间热闹 |
| 提高单人使用价值 | 单人结果及后续真实协作 | 工具用户始终不参与网络 |
| 人工撮合或补贴 | 服务结果、成本、撤除后行为 | 把被支持的结果误当自主增长 |

邀请对象要与需求相容，不默认越有名越好、供给越多越好。补贴降低初次尝试成本后，检查用户因价值继续使用，还是只等待下一张券。

### 选择启动方式

以下是实施选择，不要求叠加使用：

| 方式 | 值得试验的条件 | 需要防止的失败 |
|---|---|---|
| 邀请制 | 现有成员能识别适合参与同一任务的人，接待能力有限 | 稀缺感替代实际价值，门槛使关键角色无法加入 |
| 工具带入协作 | 单人产物天然需要他人查看、使用或共同完成 | 人为加分享按钮，却没有接收者愿意参与的任务 |
| 定向补贴启动 | 已知道关键障碍是尝试成本，能追踪后续使用和全额成本 | 无选择补贴、滥用与撤除后体验崩溃 |
| 人工补足服务 | 需求路径尚未稳定，人工能让用户实际得到结果 | 隐瞒人工介入、伪造用户、服务量增加后成本不可承担 |
| 集中场景启动 | 价值依赖同时在场或地域兼容，可组织特定窗口 | 大范围宣传带来分散用户，关键时段仍为空场 |

每种方式都要说明为何优于本次其他选择，以及退出或改用其他方式的条件。

### 设计第一次结果

交易平台检查实际成交与履约；互助社区检查是否获得可用回答；协作产品检查相关成员是否共同完成工作。入群、欢迎语和登录只是过程事件。

记录每名新用户是否获得结果及等待时间，保留失败类型；不能只访谈最活跃的人。人工介入单独标记次数和分钟数。产品层面先减小核心任务摩擦，避免为了活动堆砌功能。

### 决定何时复制

评估以下证据，不设普适数值门槛：

- 核心结果能反复兑现，成功并非只由一次活动贡献。
- 在合理使用周期内，关键角色愿意回来，失败原因可解释。
- 人工和激励需求可计量，降低支持的试验说明了哪些部分能维持。
- 新需求不会使关键角色持续超负荷，扩张所需能力已明确。

若尚无再次使用机会，不从短期留存推断失败；先验证首次价值与自然周期。

## B. 检验复制扩张

分别回答原单元为什么有效、下一单元能否获得相同条件。不能只复制活动脚本，忽略关键角色、关系基础和需求密度。

| 候选网络 | 与已有网络的真实连接 | 关键角色可得性 | 场景差异 | 成本及人力 | 证据 | 选择理由 |
|---|---|---|---|---|---|---|

可定性排序，不强制加权打分。连接可以来自跨团队项目、跨地域出行、共同兴趣或供给复用；也可能分流旧单元稀缺服务，需要核查容量。

保持可比较的启动条件、同口径结果和成本账，尽可能一次改变一个关键条件。用成熟网络对照时，说明市场、季节和团队经验差异，不能称为随机实验。

复制成功要回答：新用户是否得到结果；团队能否重复服务；额外成本是否可接受；原单元是否受损。满足项目目标后再考虑下一批规模。

## C. 改进已运转的网络

三类工作可能互相影响，一次实验优先检验一条因果链。

| 目标 | 待排查环节 | 原创实验方向 | 假阳性 |
|---|---|---|---|
| 持续交互 | 找到对象、收到响应、完成结果、再次需要 | 改善匹配、减少等待、连接下一个已验证场景 | 通知使打开次数上升，实际结果未改善 |
| 有效新用户 | 邀请、对象适配、接受、首次价值、后续使用 | 在共同任务中降低邀请阻力，改善被邀请者体验 | 邀请量增长却有重复、骚扰和低质注册 |
| 收入与成本 | 额外价值、付费意愿、直接服务成本 | 验证增值服务、付费路径及供需利用率 | 提价短期增收，关键角色退出 |

找回路损失最大的环节再选措施。归因前排除获客人群、节假日、促销、性能和埋点变化。分层看首次使用、持续使用、流失与回归；回归应有新的相关价值，不默认群发提醒就有效。

对高参与用户观察其获得结果的路径，提出让相邻用户受益的假设，再验证；不能因为高留存者使用某功能，就认定强推该功能会提高所有人的留存。

排期使用「测基线 → 小范围验证 → 完整使用周期 → 决策」。预定结束日期不代表证据必然充足。
