# 调用方式

在支持 Codex skills 的环境使用 `$cold-start-ops`。它接受自然语言，不是命令行程序；「诊断」「设计」「复盘」是任务意图，无须固定参数。

## 最短调用

```text
$cold-start-ops
我们在做【业务】，用户是【角色】，现在遇到【问题】。
请先判断网络效应是否适用，再给出最值得验证的下一步。
```

## 从零做社群

```text
$cold-start-ops
我要做一个服务跨境电商运营的互助社区，尚未建群。
团队2人，首月预算6000元，希望用户持续获得实操问题的答案。
请设计首个原子级网络，识别困难侧用户，定义首次价值事件，
给出首月行动表、实验卡和扩张条件。缺数据处标为假设。
```

## 双边平台诊断

```text
$cold-start-ops
我们做同城摄影撮合，已有摄影师，但用户说找不到合适服务。
根据我附的分城区、时段、需求类型数据，区分供给、匹配与信任问题，
确定优先处理的局部网络，并设计一次小范围实验。
```

## 复制到其他网络

```text
$cold-start-ops
协作产品在一个设计团队中已连续使用三个月，准备扩到其他部门。
分析哪些条件可复制，比较扩展顺序，设计试点并说明需要的证据。
```

## 活跃、增长或变现停滞

```text
$cold-start-ops
分析我提供的最近12周数据，按局部网络和新旧用户分组，
判断交互、获客、经济结果或增长天花板的瓶颈。
先检查口径，再推荐两项优先实验；样本不足时说明无法下结论。
```

## 只分析数据

```text
$cold-start-ops
请分析附件中不同城区的匹配成功率，先检查分母、去重和观察窗口。
只给计算结果、主要差异和证据缺口，不附加实验计划。
```

## 竞争与关键用户流失

```text
$cold-start-ops
优质供给开始同时使用竞争平台。根据访谈与数据判断原因，
比较真实收益与服务体验，提出方案并设计补贴撤除后的验证。
```

## 评审与复盘

```text
$cold-start-ops
评审下面计划的网络边界、困难侧、阶段、指标与资源安排。
只修正影响成败的部分，给出实验卡。【粘贴方案】
```

```text
$cold-start-ops
沿用上次口径复盘这些结果，区分得到支持与未被验证的假设，
给出继续、修改、停止或扩张的决定。
【粘贴原实验卡、执行记录、数据和异常】
```

## 无数字也能开始

提供产品、用户、互动和卡点即可，先做机制诊断与采集设计，不凭空生成预算、留存率或预测。

## 自动触发

「按《冷启动》的网络效应方法，帮我诊断这个社区为什么没人回应。」

「优化服务器冷启动」或「写三条广告」不应触发本 skill。

仅问书目、概念解释或笼统说“优化运营”时，也不自动进入整套运营工作流。显式调用后发现业务不适用，应给适用性判断及与问题相关的下一步。
